# Apple's canonical toll-free bridged types — the authority for what this tree's bridge may reach.
#
# WHY THIS FILE EXISTS. docs/design/foundation-cf-core-plan.md §2 enumerates the bridged class set the whole
# campaign is scoped to, and that enumeration was derived by hand. Apple publishes THE list — Table 1 of
# "Toll-Free Bridged Types" in Core Foundation Design Concepts — so the scope has an authority, and a
# hand-written list that disagrees with it is simply wrong. It disagreed; the plan has been corrected against
# this file (2026-10-04).
#
# SOURCE: https://developer.apple.com/library/archive/documentation/CoreFoundation/Conceptual/CFDesignConcepts/Articles/tollFreeBridgedTypes.html
# Table 1, transcribed verbatim: three columns, twenty-six rows, twenty-five distinct NS classes (CFBooleanRef
# and CFNumberRef both bridge to NSNumber). This file is a TRANSCRIPTION, not a generated artefact, which is
# why the URL is here and why re-fetching is manual: re-diff it whenever the campaign's scope is revisited.
#
# TWO READING RULES THAT MATTER MORE THAN THE ROWS DO:
#
#  1. THE TABLE IS CLASSES ONLY, AND BRIDGING IS ABOUT IDENTITY RATHER THAN LAYOUT. A bridged pair is ONE
#     object under two names: the same pointer is both a valid CFTypeRef and a valid Objective-C receiver. A
#     STRUCT is not in this table and cannot be, however identical its bytes — CFRange and NSRange are two
#     VALUES with the same layout, which is a different thing. The two range spellings even diverge across
#     eras: Apple's own 10.2 SDK declares `NSRange {unsigned int location; unsigned int length;}` (8 bytes)
#     where modern Apple and this tree declare NSUInteger (16 bytes, matching CFRange's two signed longs). So
#     "toll-free bridge a CFRange to an NSRange" is a category error in Apple's terms: what a range needs is a
#     LAYOUT PROOF and a pair of checked converters, never a bridge claim.
#
#  2. THE `bridging` COLUMN IS THE BRIDGING'S AVAILABILITY, NOT THE CLASS'S, AND HERE THE TWO DISAGREE.
#     Measured against docs/reference/foundation-era.txt (Apple's page metadata, which records the CLASS):
#     every class in this table is introducedAt 10.0, while the table dates the BRIDGING at 10.4 for
#     NSAttributedString/NSCalendar/NSLocale and 10.5 for NSError. Neither ground may be used to filter the
#     other — they measure different events.
#
# AND THE NEGATIVE IS AS USEFUL AS THE POSITIVE, because names mislead. Apple's own prose names three:
# "NSRunLoop is not toll-free bridged to CFRunLoop, NSBundle is not toll-free bridged to CFBundle, and
# NSDateFormatter is not toll-free bridged to CFDateFormatter." §2 of the plan listed NSRunLoop as bridged.
#
